# Security Policy

## Supported Versions

This project is under active development. Security fixes are applied to the `main` branch only.

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please **do not open a public GitHub issue**.

Instead, contact the maintainer directly by opening a private security advisory on GitHub (if the repository has this feature enabled) or by emailing the address listed in the repository contact information.

Please include:

- A clear description of the vulnerability.
- The component or file path affected.
- Steps to reproduce.
- Any proof-of-concept code.
- Your assessment of the impact.

We will acknowledge your report as soon as possible and aim to provide an initial assessment within a reasonable timeframe. We do not currently have a formal bug bounty programme.

## Disclosure Policy

We follow a coordinated disclosure approach:

1. Maintainer acknowledges the report.
2. Maintainer investigates and prepares a fix.
3. Fix is released.
4. Vulnerability is disclosed publicly after the fix is available.

Please do not publish details of a vulnerability until a fix has been released.

## Out of Scope

The following are not considered security vulnerabilities in this context:

- Issues in third-party dependencies (please report them upstream).
- Denial of service attacks that require physical access.
- Social engineering attacks.

## Known Limitations

See [`docs/security.md`](docs/security.md) for a complete list of known security limitations and recommended improvements.
